# 经理公共规则

工程与源码维护规则见项目根 `AGENTS.md`。本目录收纳经理工作区；个人入口引用共同规则，
并登记各自的职责、授权、业务身份及实际路径。

## 职责与任务投递

- 经理管理配置、账号人设、授权、计划及功能版本；员工操作本机账号、执行任务并回传结果。
- 用户要求拟定或审核指标时，先给出账号、目标、素材组和批次时间，按已确认方案下发；
  用户直接要求下发或补齐且授权已明确时，执行投递。
- 下发链路：生成任务 JSON → SSH/SFTP 投递员工 `inbox` → `wake-task` 唤醒 →
  员工领取执行 → 写入 `outbox` → 经理回收、去重导入并更新业务汇总。
- 机器配置是项目、inbox、outbox 和账号槽位路径的读取依据。新员工两端路径验证一致后接入。
- 分别报告 `TASK_ACK`、Agent 领取、业务完成、outbox 写入和经理导入。
  只要求下发时，收到接收确认后交由后台执行，本轮结束；用户要求检查进度或完成情况时，
  再核对业务回执与未完成原因。
- 下发超时、经理状态锁占用或唤醒结果未知时，先按原任务 ID 核对经理记录和员工
  inbox/outbox；确认送达与领取后处理，保持原业务动作身份。
- 每日指标按批次安排时，一次保存各批时间及前后顺序。同机账号按队列串行。
  每批目标是本批新增量，全天目标用于汇总，各批分别验收。

## 账号策略与周期管理

- 账号槽位位于员工机；账号人设以“机器 + 槽位”隔离。人设调整沿同一 `persona_id` 保存版本，
  已下发任务采用创建时的快照。
- 经理管理每 20 分钟的周期策略、运行时段、账号开关及评论/私信回复开关，员工本地定时触发。
  同一用途配置一套周期调度，明确暂停的账号保持暂停。
- 每轮固定待处理事件集合，沿用账号人设、知识与开关；后续新增事件留给下一轮。
- 配置页面显示最近采集、下次巡检、待处理数量和回传状态；生效情况以员工实际验证为准。
- 机器例外按当前配置和用户安排登记。PC052 普通业务复用绑定槽位身份。

## 素材与数据回收

- 本机素材来源为 `C:\小红书Mila文件存档\素材`。按账号和素材系列保存上次实际成功组号，
  接续使用下一组。下发前核对图片与文案，员工接收后核对文件数量和字节数。
  原发布结果未知时先对账，再决定是否接续或使用原草稿。
- 数据回收核对员工实际执行及回执生成、回执传至经理、经理数据库导入三步，
  分别报告记录和同步时间。页面展示问题独立按界面职责排查。
- 经理汇总沿现有 `manager-operations.db` 权威记录；任务文件材料和交付证据归任务工作区。
  持久业务记录由既有存储维护，角色 manifest 引用存储位置。

## 查询与验收

- 先用固定入口 `scripts/manager_cli.py database schema` 发现字段，再通过
  `database query --input-file <绝对路径>` 执行只读 SQL。查询 JSON 含 sql、parameters、limit。
- 查询库位于经理状态目录。`records/fields` 保存经理原始记录，
  `worker_records/worker_fields` 按机器隔离员工业务表；先看 metadata 同步时间。
- `acceptance` 返回动作目标、确认实际数、账号和证据，支持日期与机器:槽位筛选。
  历史成功和本轮结果分别说明。完整指引见项目根 `docs/OPERATIONS-ACCEPTANCE-DATABASE.md`。

## 故障与发布管理

- 员工失败回执沿现有 outbox 自动报障；`report-bug` 可补充现象和证据。
- 经理使用 `debug list/claim` 领取工单，在项目分支修改权威源码并补回归测试，
  通过 `diagnose/build` 登记诊断和构建修复包。
- 通过 `dispatch/apply/reconcile/verify/accept` 完成送达、安装、回执核对、服务验证和验收。
  员工运行任务时顺延安装，安装后保持暂停，按运营安排恢复。
- 原任务结果未知时核对原执行证据；调试、部署和业务结果分别登记。
  操作及回退方法见项目根 `docs/DEBUG-WORKFLOW.md`。
- 功能安装后先登记停用，再显式选择正式或试用版本及经理、设备、账号、动作范围。
  任务携带 `function_id` 与 `allowed_function_versions`，执行结果保留功能和项目实际版本。

## 工作材料

经理工作区保存个人规则、身份路径索引、经理业务版本、Worker源版本及包配套关系。
`run_data/` 沿原任务身份保存输入、回执、中间产物和交付证据，`logs/` 保存过程日志，
`migration/` 保存切换、回退及验收引用。项目完整文档与记忆库由工程基准维护并按主题引用。
