# auto-xhs 故障恢复

本文以当前工作区实现为准。V1.5 的账号联合启动和 Agent/Python CLI 分步发布已经完成自动化测试，
仍需真实设备验收；私信执行链已完成自动化测试但尚未真实发送验收；V2.0 智能回复只开放待人工
确认草稿。后台规则化自动回复和公开资料修改仍未开放。

## WebUI 打不开

再次双击 `start-auto-xhs.cmd`。启动器会优先复用已有服务；若端口被其他程序占用，会显示明确
错误。不要同时重复打开多个启动窗口。

如果错误中包含 `ModuleNotFoundError: No module named 'websockets'`，表示 Web 控制台所需的
运行依赖没有安装到项目虚拟环境。在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

完成后重新运行 `start-auto-xhs.cmd`。`websockets` 已在项目的 `pyproject.toml` 中声明，正常首次
启动会由 `scripts/bootstrap.ps1 -Prepare` 自动安装；更新代码或复制了不完整的 `.venv` 时可以用
上述命令修复。

## 账号一直是“需处理”

按账号卡片的“下一步”处理，常见顺序是：点击“启动账号”恢复 Bridge 和绑定 Profile、完成扩展
配对、检查当前 UID。仅 Bridge 在线不等于账号就绪。

V1.5 联合启动完成后，“启动账号”会先恢复 Bridge，再在扩展未连接时打开绑定 Profile。若出现
`PROFILE_MISMATCH`，说明实际连接的 Profile 或扩展实例与槽位不一致；系统不得改用其他已打开
窗口，也不得误报 READY。

## Profile 或 UID 不一致

立即暂停全部任务，核对当前 Chrome 窗口是否属于目标 Profile。不要直接覆盖原 UID，也不要通过
切换账号来“碰运气”。回到正确 Profile 后重新执行只读 UID 检查；若确实要更换槽位身份，按换号
流程单独确认。

## Bridge 无法启动或停止

先刷新账号状态。停止和重启只操作本项目登记的 PID；如果提示“没有找到由本项目登记的 Bridge
进程”，说明当前端口可能来自旧进程或其他程序，导出诊断后人工核对，不要强制结束未知进程。

## 任务进入 BLOCKED

查看任务的 `recommended_action`。恢复账号 READY 后创建新任务；系统不会自动补跑离线期间的任务。

如果错误为 `CAPABILITY_DISABLED` 或“能力未实现”，先核对具体能力：旧版一步发布、公开资料修改、
指定评论点击即直发和后台规则化自动回复仍未开放；分步发布、私信和智能回复草稿则必须从各自的
受控入口创建。不要调用底层兼容命令或外部工具绕过服务层限制。

## 发布停在 preview_ready

这表示 Agent/CLI 已填写发布页，但尚未取得用户对真实浏览器预览的确认。在“确认中心”打开该单个
任务，核对 Profile、昵称、UID、标题、正文、素材、可见范围和发布时间。确认发布前必须勾选已经
检查真实预览；不发布时可以保存草稿。账号、UID 或任务阶段不一致时应重新核对，不要强行确认。

## 智能回复提示 LLM_NOT_CONFIGURED

在“系统 → 智能回复模型”填写兼容服务的接口地址、模型和 API Key，再显式点击“测试连接”。测试
连接只请求模型，不采集评论或执行小红书写操作。配置成功后回到“确认中心”重新为明确事件生成草稿。
生成草稿仍不会自动发送。

## 任务是 RESULT_UNKNOWN

这表示请求可能已经到达平台，但系统没有得到可靠结果。先在小红书页面人工检查实际状态，再决定
下一步。评论、回复、点赞和收藏都不要直接重复发送。

## 达到配额、重复目标或熔断

等待配额窗口恢复，或在设置页明确调整限制。熔断通常意味着同一账号近期连续失败，先解决连接、
页面状态或平台限制，再恢复操作。

## 如何提供诊断

在设置区域点击“导出脱敏诊断”，界面会显示本机文件路径。报告会移除 Bridge Token、配对信息、
Cookie、验证码和页面令牌；发送前仍建议用户自己打开并浏览一次内容。
