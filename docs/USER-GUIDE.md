# auto-xhs V1 使用说明

适用版本：V1 本地多账号运营控制台
适用系统：Windows 10/11
适用用户：希望用 WebUI 或 Codex 管理多个小红书账号的个人运营者

## 1. 先了解 V1 能做什么

V1 已开放：

- 添加最多 6 个常用账号槽位；
- 绑定本机已有 Chrome Profile；
- 检查 Bridge、扩展、Profile 和当前小红书 UID；
- 浏览首页、搜索笔记；
- 在配额和重复检查下点赞、取消点赞、收藏、取消收藏；
- 保存评论或回复草稿，并在确认最终文本后执行；
- 从首页推荐中随机选择 1–3 篇笔记，生成相关评论并在当前点击授权后直接发送；
- 查看任务状态和执行记录；
- 全局暂停任务、调整并发和 L1 配额、导出脱敏诊断。

V1 不开放：

- 发布图文、视频或长文；
- 定时发布；
- 私信和公开资料修改；
- 自动打开、关闭或切换 Chrome；
- 未经当前任务点击授权自动发送评论或回复。

项目代码中可能保留后续版本的底层命令，但不代表 V1 可以使用这些能力。

## 2. 使用前准备

准备以下环境：

- Windows 10 或 Windows 11；
- Google Chrome；
- 一个或多个已经登录小红书的 Chrome Profile；
- 项目文件夹；
- Python 3.11 或更高版本。没有 Python 时，可在明确同意后使用项目引导器准备。

项目只操作你选定的本机 Chrome Profile。不要把手机号、密码、验证码、Cookie 或配对信息写进
账号槽位名称、项目文件或 GitHub。

## 3. 在新电脑取得项目

### 方法 A：使用 Git

```powershell
git clone https://github.com/xiaoquan661/auto-xhs.git
cd auto-xhs
```

如果仓库是私有仓库，Git Credential Manager 会要求在浏览器登录有仓库访问权限的 GitHub 账号。

### 方法 B：下载 ZIP

在 GitHub 仓库页面选择 **Code → Download ZIP**，解压后进入项目根目录。ZIP 方式可以运行项目，
但后续更新需要重新下载或改用 Git。

## 4. 第一次启动

在项目根目录双击：

```text
start-auto-xhs.cmd
```

启动器会：

1. 检查本项目可用的 Python；
2. 准备项目依赖；
3. 启动或复用本地 WebUI；
4. 打开 `http://127.0.0.1:8765`。

WebUI 只监听本机地址，局域网和互联网不能直接访问。

如果提示没有 Python，先确认允许为本项目准备运行环境，再在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1 -Prepare -InstallMissingPython
```

完成后重新双击 `start-auto-xhs.cmd`。不要在脚本没有返回 `python_missing` 时重复安装运行环境。

## 5. 添加第一个账号

进入 WebUI 的“添加账号”。

### 推荐：绑定已有 Chrome Profile

1. 槽位名称填写本机别名，例如 `brand-a` 或 `shop-1`；
2. 添加方式选择“绑定已有 Chrome Profile”；
3. 点击“扫描 Profile”；
4. 选择目标 Profile；
5. 点击“确认添加”。

槽位名称不是手机号，也不是小红书号。一个 Chrome Profile 只能绑定到一个槽位。

### 高级：新建独立槽位

“新建独立槽位”会创建新的本地 Chrome 用户数据目录，但系统仍不会自动打开 Chrome，WebUI 也
暂未提供一键打开按钮。普通用户优先使用已有 Profile；独立环境只建议熟悉 Chrome 启动参数的
用户使用。

## 6. 加载通用浏览器扩展

所有账号 Profile 共用同一份扩展代码，但配对状态分别保存在各自 Profile 中。

默认扩展目录就是当前项目中的：

```text
<项目根目录>\extension
```

对每个需要使用的 Chrome Profile 分别执行：

1. 手动打开正确的 Chrome Profile；
2. 地址栏进入 `chrome://extensions/`；
3. 打开右上角“开发者模式”；
4. 点击“加载已解压的扩展程序”；
5. 选择当前项目根目录中的 `extension` 文件夹；
6. 将扩展固定在 Chrome 工具栏，方便查看状态。

项目升级扩展后，需要在 `chrome://extensions/` 中点击一次“重新加载”。

不要加载 `%USERPROFILE%\.codex\skills\xiaohongshu-skills` 中的旧开发副本。若账号是在旧版本中
创建、配置仍指向 `%USERPROFILE%\.xhs\universal-extension`，先保留现状；确认迁移时再执行
`account-sync` 更新槽位配置，并在对应 Chrome Profile 中重新加载当前项目的 `extension`。

## 7. 启动 Bridge 并完成配对

回到 WebUI 的账号卡片：

1. 点击“启动 Bridge”；
2. 确认目标 Chrome Profile 已经打开；
3. 点击“发起配对”；
4. 配对信息复制成功后，打开目标 Profile 的扩展弹窗；
5. 粘贴并确认配对信息；
6. 回到 WebUI 刷新状态。

配对信息短时有效且只能使用一次。每个 Profile 必须分别配对，不能把一个账号的配对信息粘贴到
另一个 Profile。

## 8. 检查并确认 UID

扩展连接后，在账号卡片点击“检查并确认 UID”。

WebUI 会读取当前 Profile 已登录的小红书昵称和 UID。确认显示的是目标账号后，再记录到该槽位。

账号必须依次通过以下检查才会显示“已就绪”：

```text
Bridge 在线
→ 扩展已连接
→ Profile 与槽位一致
→ 当前 UID 已读取
→ 当前 UID 与槽位记录一致
→ READY（已就绪）
```

如果显示“身份不一致”，立即暂停任务并检查是否打开了错误 Profile，不要直接覆盖原 UID。

### 退出与半自动换号

账号卡片中的“退出当前账号”会自动结束当前小红书登录，并在回读到明确的未登录状态后才提示成功。
“切换账号”会先完成同样的退出核验，然后由你在对应 Chrome Profile 中手动登录新账号，最后
回到控制台核验新 UID。若页面仍能读到旧账号，流程会停在第一步并显示真实失败原因。

### 删除账号槽位

在账号卡片右上角点击“更多 → 删除槽位”，再输入完整槽位名称确认。系统会取消该槽位尚未
开始的任务、停止受管 Bridge、关闭自启动、撤销配对，并将槽位数据保存到本机归档。
Chrome Profile、小红书登录数据和共享通用扩展不会被删除；有运行中任务或未登记 Bridge 时，
控制台会阻止删除并提示先处理。

## 9. 使用 WebUI 执行任务

每个账号卡片都会显示该槽位当前是“空闲”“等待执行”“执行中”还是“需处理”。任务表单的账号
下拉框也会显示相同状态：一个账号有未完成任务时，不能对它重复创建任务；你仍可切换到另一个
已就绪且空闲的账号并行执行。运行期间控制台会自动刷新任务状态。

### 浏览首页

1. 在“任务与确认 → 直接任务”选择目标账号；只有 READY 账号可以提交，页面会优先选择 READY 账号；
2. 任务类型选择“浏览首页”；
3. 任务目标可以留空，也可以填写便于识别的备注，例如“今日首页”；
4. 点击“创建并执行”。

### 搜索笔记

1. 选择目标账号；
2. 任务类型选择“搜索笔记”；
3. 输入关键词；
4. 点击“创建并执行”。

WebUI 当前主要展示任务状态和结果摘要。需要查看、筛选和总结完整搜索结果时，优先直接让 Codex
在明确的账号槽位中执行搜索。

### 点赞或收藏

1. 选择已经 READY 的目标账号；
2. 选择“点赞/取消点赞”或“收藏/取消收藏”；
3. 填写目标笔记 ID；
4. 填写该笔记当前的 XSEC Token；
5. 取消操作时勾选对应复选框；
6. 创建并执行。

笔记 ID 和 XSEC Token 通常来自当前笔记链接、搜索结果或 Codex 的搜索/详情步骤。不要复用其他
笔记或已经失效的 Token。

系统会检查账号身份、每小时/每日配额、短时间重复目标和近期连续失败。被阻止时先按页面提示
恢复，不要连续点击。`BLOCKED` 任务会显示具体原因和推荐动作；恢复账号后点击“重试”，或者点击
“取消”结束该任务。提交期间按钮会锁定，避免一次操作创建多条重复任务。

## 10. 评论和回复

### 随机评论

1. 在“立即任务”中选择已经 READY 的目标账号；
2. 任务模板选择“随机评论”；
3. 选择评论风格，并设置发送数量、候选池和最长搜集时间；
4. 点击“创建并直接发送”。

系统会从首页推荐中搜集候选，随机抽取 1–3 篇，读取笔记标题和正文，生成相关评论后直接发送。
这次点击只授权当前账号和本次显示的数量；不会进入逐条确认，也不会建立后台持续评论计划。任务结束后
可展开结果查看每篇目标笔记、实际评论文本和成功或失败状态。

### 指定笔记评论和回复

评论和回复在“外发草稿确认”中采用“先保存、再确认、后执行”：

1. 选择目标账号；
2. 选择“评论笔记”或“回复评论”；
3. 评论填写笔记 ID，回复填写评论 ID；
4. 填写目标说明，帮助确认时识别对象；
5. 编辑最终文本并保存草稿；
6. 点击“核对并确认”；
7. 核对账号、UID、目标和完整文本；
8. 输入目标笔记 ID 与当前 XSEC Token 后执行。

草稿一旦修改，旧确认自动失效；一次确认只能执行一次。
重新确认同一草稿时，上一份尚未使用的确认也会失效。成功执行后草稿显示“已执行”；结果无法
确认时显示“结果待核对”。

若结果显示 `RESULT_UNKNOWN`，表示平台可能已经收到操作，但系统没有得到可靠结果。必须先打开
小红书页面人工检查，不能直接重发。

## 11. 使用 Codex 操作

在 Codex 中打开本项目工作区后，用自然语言明确说出账号槽位和目标。例如：

```text
使用 brand-a 搜索“露营装备”，只读取结果，不点赞。
```

```text
使用 brand-b 搜索“手冲咖啡”，找出互动最高的三篇并总结。
```

```text
为 brand-a 的这篇笔记准备一条评论草稿，但不要发送。
```

涉及点赞、收藏、评论或回复时，应明确目标账号。评论和回复仍需在 WebUI 核对最终草稿；发布和
私信不会因为使用 Codex 而开放。

## 12. 多账号使用原则

- 每个槽位对应一个固定 Chrome Profile；
- 不同账号任务可以并行；
- 同一个账号的任务自动串行；
- 用户手动保持目标 Chrome Profile 和小红书页面在线；
- 切换小红书登录身份前，先暂停该账号业务；
- 电脑迁移、扩展重装或撤销配对后，需要重新配对；
- 普通重启不需要重新配对。

## 13. 暂停、配额和自启动

- 顶部“暂停全部任务”会阻止新任务开始，不会强行中断已经到达平台的动作；
- 全局并发可以设置为 1–3；
- L1 设置包含每小时限额、每日限额、重复目标间隔和失败熔断阈值；
- 账号卡片可以启用 Windows 登录时恢复 Bridge；
- Bridge 自启动不会自动启动 Chrome。

修改配额和自启动属于运行配置变更，WebUI 会要求再次确认。

## 14. 查看结果

任务可能出现以下状态：

| 状态 | 含义 | 应对方式 |
|---|---|---|
| `SUCCESS` | 已获得明确成功结果 | 查看执行记录 |
| `BLOCKED` | 条件不满足，任务没有正常开始 | 按推荐动作恢复账号 |
| `FAILED` | 已获得明确失败结果 | 修复参数或连接后重新创建任务 |
| `RESULT_UNKNOWN` | 可能已执行，但结果无法确认 | 先到平台人工检查，不能直接重发 |

账号未就绪导致的 `BLOCKED` 也会进入执行记录，便于追踪为什么没有开始。恢复后可以在任务卡片
点击“重试”；不再需要的排队中、待确认或阻塞任务可以取消。

## 15. 日常启动和关闭

日常使用：

1. 手动打开需要使用的 Chrome Profile；
2. 保持目标小红书页面登录；
3. 双击 `start-auto-xhs.cmd`；
4. 刷新 WebUI，确认目标账号 READY；
5. 再执行任务。

关闭 WebUI 页面不等于停止后台 Bridge。正常使用时可以让 Bridge 保持运行；不要在任务执行期间
直接结束未知 Python 或 Chrome 进程。

## 16. 诊断与故障恢复

遇到问题时先查看账号卡片的“下一步”。还不能解决时，在设置区点击“导出脱敏诊断”，报告会
保存到本机产品数据目录。

详细恢复步骤见 [故障恢复指南](TROUBLESHOOTING.md)。

## 17. 本地数据位置

默认数据位置：

```text
账号槽位：%USERPROFILE%\.xhs\accounts
通用扩展代码：<项目根目录>\extension
任务与诊断：%USERPROFILE%\.xhs\auto-xhs
```

删除项目目录不会自动删除这些数据。卸载或迁移前，先确认是否需要保留任务记录和账号槽位。

不要把以上目录、Chrome Profile、配对信息或诊断中的私密内容提交到 GitHub。

## 18. 最短上手清单

```text
取得项目
→ 双击 start-auto-xhs.cmd
→ WebUI 添加已有 Chrome Profile
→ 在目标 Profile 加载通用扩展
→ 启动 Bridge
→ 发起并完成配对
→ 检查并确认 UID
→ 账号显示 READY
→ 先执行一次搜索测试
→ 再使用点赞、收藏或草稿确认功能
```

完成这条链路后，再逐个添加其他账号。
