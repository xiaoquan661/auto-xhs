# auto-xhs 使用说明

稳定基线：V1.0 本地多账号运营控制台
增量能力：V1.5 分批实现中；V2.0 提供 Codex 评论与入站私信上下文回复
适用系统：Windows 10/11
适用用户：希望用 WebUI 或 Codex 管理多个小红书账号的个人运营者

## 1. 先了解版本边界

当前稳定基础能力：

- 添加最多 6 个常用账号槽位；
- 绑定本机已有 Chrome Profile；
- 检查 Bridge、扩展、Profile 和当前小红书 UID；
- 浏览首页、搜索笔记；
- 在配额和重复检查下点赞、取消点赞、收藏、取消收藏；
- 保存评论或回复草稿，并在确认最终文本后执行；
- 从首页推荐中随机选择 1–3 篇笔记，生成相关评论并在当前点击授权后直接发送；
- 查看任务状态和执行记录；
- 全局暂停任务、调整并发和 L1 配额、导出脱敏诊断。

增量能力必须按下表区分自动化测试与真实账号验收，不能因为代码入口已经存在就把真实平台结果描述为已验证：

| 能力 | 当前规则 | 工作区状态 |
|---|---|---|
| 发布和定时发布 | Agent/CLI 生成并正式发布，回读后记录结果 | 自动化测试完成，真实发布待验收 |
| 评论 | 指定评论/回复保留最终文本确认；随机评论仍限定 1–3 条 | 当前确认链可用；指定评论点击即直发仍未开放 |
| Codex 入站回复 | Codex 读取评论或私信上下文并提交结构化决策 | `reply-inbox`、规则复核、发送回读和专用 Skill 已通过自动化测试；真实账号待验收 |
| API 模型回复 | 用户按账号启用规则后，由 `reply-cycle` 运行兼容回复周期 | 自动化测试完成；真实账号待验收 |
| 私信 | 主动批次由 Agent/CLI 下发；收到的新私信由 Agent 智能回复 | 主动执行器、收件箱采集、上下文校验和发送回读已测试；真实账号待验收 |
| 公开资料修改 | 展示修改前后差异，确认后执行 | 未实现 |
| 登录 | 自动退出、用户手动登录、核验新 UID | 半自动换号链已测试 |
| 启动账号 | 先启动 Bridge，扩展未连接再自动打开绑定 Profile | 自动化测试完成，真实 Windows 待验收 |

真实账号写操作仍需明确目标和授权；没有平台/UI 回读时按 `RESULT_UNKNOWN` 处理，不能把自动化测试
当成真实发布、私信或回复成功的证据。

## 2. 使用前准备

准备以下环境：

- Windows 10 或 Windows 11；
- Google Chrome；
- 一个或多个已经登录小红书的 Chrome Profile；
- 项目文件夹；
- Python 3.11 或更高版本。没有 Python 时，可在明确同意后使用项目引导器准备。
- 项目运行依赖。Web 控制台和 Bridge 需要 `websockets`，相关依赖由首次启动时的
  `scripts/bootstrap.ps1 -Prepare` 安装到项目 `.venv`。

项目只操作你选定的本机 Chrome Profile。不要把手机号、密码、验证码、Cookie 或配对信息写进
账号槽位名称、项目文件或 GitHub。

## 3. 在新电脑取得项目

### 方法 A：使用 Git

```powershell
git clone https://github.com/xiaoquan661/auto-xhs.git
cd auto-xhs
```

如果仓库是私有仓库，Git Credential Manager 会要求在浏览器登录有仓库访问权限的 GitHub 账号。

### 方法 B：下载 ZIP

在 GitHub 仓库页面选择 **Code → Download ZIP**，解压后进入项目根目录。ZIP 方式可以运行项目，
但后续更新需要重新下载或改用 Git。

## 4. 第一次启动

在项目根目录双击：

```text
start-auto-xhs.cmd
```

启动器会：

1. 检查本项目可用的 Python；
2. 准备项目依赖；
3. 启动或复用本地 WebUI；
4. 打开 `http://127.0.0.1:8765`。

WebUI 默认监听 `0.0.0.0:8765`，支持本机和同一局域网访问。其他电脑使用
`http://<经理机局域网 IPv4 地址>:8765/` 打开；地址可在经理机的 `ipconfig` 输出中查看。
经理机需要保持运行，Windows 防火墙需允许来自 `LocalSubnet` 的 TCP 8765 入站连接。

更新运行中的服务后，在项目目录执行一次重启，让监听设置生效：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/restart-webui.ps1
```

网页内重启会沿用当前监听地址。需要仅本机访问时，可执行
`scripts/restart-webui.ps1 -ListenAddress 127.0.0.1`。

如果提示没有 Python，先确认允许为本项目准备运行环境，再在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1 -Prepare -InstallMissingPython
```

完成后重新双击 `start-auto-xhs.cmd`。不要在脚本没有返回 `python_missing` 时重复安装运行环境。

如果电脑上已经有 Python，但启动时提示缺少 `websockets`，说明项目虚拟环境的依赖没有完整安装
或更新。请在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

安装完成后重新双击 `start-auto-xhs.cmd`。控制台应使用项目 `.venv` 中的 Python，不要改用一个
没有安装项目依赖的系统 Python。

## 5. 添加第一个账号

进入 WebUI 的“添加账号”。

### 推荐：绑定已有 Chrome Profile

1. 槽位名称填写本机别名，例如 `brand-a` 或 `shop-1`；
2. 添加方式选择“绑定已有 Chrome Profile”；
3. 点击“扫描 Profile”；
4. 选择目标 Profile；
5. 点击“确认添加”。

槽位名称不是手机号，也不是小红书号。一个 Chrome Profile 只能绑定到一个槽位。

### 高级：新建独立槽位

“新建独立槽位”会创建新的本地 Chrome 用户数据目录。V1.0 不会自动打开 Chrome，WebUI 也暂未
提供一键打开按钮；普通用户优先使用已有 Profile。V1.5 联合启动完成后，扩展未连接时可以自动
打开该槽位绑定的 Profile。

## 6. 加载通用浏览器扩展

所有账号 Profile 共用同一份扩展代码，但配对状态分别保存在各自 Profile 中。

默认扩展目录就是当前项目中的：

```text
<项目根目录>\extension
```

对每个需要使用的 Chrome Profile 分别执行：

1. 手动打开正确的 Chrome Profile；
2. 地址栏进入 `chrome://extensions/`；
3. 打开右上角“开发者模式”；
4. 点击“加载已解压的扩展程序”；
5. 选择当前项目根目录中的 `extension` 文件夹；
6. 将扩展固定在 Chrome 工具栏，方便查看状态。

项目升级扩展后，需要在 `chrome://extensions/` 中点击一次“重新加载”。

不要加载 `%USERPROFILE%\.codex\skills\xiaohongshu-skills` 中的旧开发副本。若账号是在旧版本中
创建、配置仍指向 `%USERPROFILE%\.xhs\universal-extension`，先保留现状；确认迁移时再执行
`account-sync` 更新槽位配置，并在对应 Chrome Profile 中重新加载当前项目的 `extension`。

## 7. 启动 Bridge 并完成配对

回到 WebUI 的账号卡片。以下是 V1.0 当前流程：

1. 点击“启动 Bridge”；
2. 确认目标 Chrome Profile 已经打开；
3. 点击“发起配对”；
4. 配对信息复制成功后，打开目标 Profile 的扩展弹窗；
5. 粘贴并确认配对信息；
6. 回到 WebUI 刷新状态。

配对信息短时有效且只能使用一次。每个 Profile 必须分别配对，不能把一个账号的配对信息粘贴到
另一个 Profile。

## 8. 检查并确认 UID

扩展连接后，在账号卡片点击“检查并确认 UID”。

WebUI 会读取当前 Profile 已登录的小红书昵称和 UID。确认显示的是目标账号后，再记录到该槽位。

首次绑定完成后，日常操作和恢复连接使用已绑定 UID，服务重启后继续有效。
手动更换登录账号时重新核验并绑定新 UID；点击“检查身份”只读取当前页面已有的身份信息，保持当前页面位置。

账号必须依次通过以下检查才会显示“已就绪”：

```text
Bridge 在线
→ 扩展已连接
→ Profile 与槽位一致
→ 槽位 UID 已确认绑定
→ 已知登录状态与绑定一致
→ READY（已就绪）
```

如果显示“身份不一致”，立即暂停任务并检查是否打开了错误 Profile，不要直接覆盖原 UID。

### 退出与半自动换号

账号卡片中的“退出当前账号”会自动结束当前小红书登录，并在回读到明确的未登录状态后显示
“退出成功，当前无账号”。卡片会提示在绑定的 Chrome Profile 中手动登录账号；登录完成后点击
“我已登录，完成核验”，系统从当前页面读取 UID；当前页未提供身份时提示待确认。
“切换账号”会先完成同样的退出核验，然后由你在对应 Chrome Profile 中手动登录新账号，最后
回到控制台核验新 UID。若页面仍能读到旧账号，流程会停在第一步并显示真实失败原因。

### 管理账号当前任务

账号卡片会独立显示账号就绪状态和当前任务状态。排队任务可以直接“取消等待”；运行中的任务
可以“终止当前任务”，系统会停止该账号的自动化连接来中断当前执行，Chrome 保持打开。涉及
平台写入的任务在终止后会进入“结果待核对”，先检查平台实际状态再决定后续操作。服务重启前
尚未开始的排队任务会转为“需处理”，可在任务页重试或取消。

### 删除账号槽位

在账号卡片右上角点击“更多 → 删除槽位”，再输入完整槽位名称确认。系统会取消该槽位尚未
开始的任务、停止受管 Bridge、撤销配对，并将槽位数据保存到本机归档。
Chrome Profile、小红书登录数据和共享通用扩展不会被删除；有运行中任务或未登记 Bridge 时，
控制台会阻止删除并提示先处理。

## 9. 使用 WebUI 执行任务

WebUI 现在定位为本地工作台，按“今日总览、账号、任务、确认中心、执行记录、系统”分区。页面保留
下面已经存在的任务入口，并统一展示账号、任务和结果。主加、私信及后续新增运营能力默认由
Agent/Python CLI 下发；发布由 Agent/CLI 连续完成填写、正式提交和平台回读。

每个账号卡片都会显示该槽位当前是“空闲”“等待执行”“执行中”还是“需处理”。任务表单的账号
下拉框也会显示相同状态：一个账号有未完成任务时，不能对它重复创建任务；你仍可切换到另一个
已就绪且空闲的账号并行执行。运行期间控制台会自动刷新任务状态。

### 浏览首页

1. 在“任务与确认 → 直接任务”选择目标账号；只有 READY 账号可以提交，页面会优先选择 READY 账号；
2. 任务类型选择“浏览首页”；
3. 任务目标可以留空，也可以填写便于识别的备注，例如“今日首页”；
4. 点击“创建并执行”。

### 搜索笔记

1. 选择目标账号；
2. 任务类型选择“搜索笔记”；
3. 输入关键词；
4. 点击“创建并执行”。

WebUI 当前主要展示任务状态和结果摘要。需要查看、筛选和总结完整搜索结果时，优先直接让 Codex
在明确的账号槽位中执行搜索。

### 点赞或收藏

1. 选择已经 READY 的目标账号；
2. 选择“点赞/取消点赞”或“收藏/取消收藏”；
3. 填写目标笔记 ID；
4. 填写该笔记当前的 XSEC Token；
5. 取消操作时勾选对应复选框；
6. 创建并执行。

笔记 ID 和 XSEC Token 通常来自当前笔记链接、搜索结果或 Codex 的搜索/详情步骤。不要复用其他
笔记或已经失效的 Token。

系统会检查账号身份、每小时/每日配额、短时间重复目标和近期连续失败。被阻止时先按页面提示
恢复，不要连续点击。`BLOCKED` 任务会显示具体原因和推荐动作；恢复账号后点击“重试”，或者点击
“取消”结束该任务。提交期间按钮会锁定，避免一次操作创建多条重复任务。

### V1.5 Agent 发布流程

图文、视频、长文、草稿和定时发布统一采用：

```text
用户向 Agent 提交发布要求并选择目标账号
→ 填写标题、正文、素材、标签、可见范围和可选发布时间
→ Agent 调用 Python CLI 创建任务并填写发布页
→ 正式发布并回读平台结果
→ WebUI 持续显示执行中和最终结果
```

图文用 `publish`，视频用 `publish-video`；填写命令也会正式提交。长文完成排版后，
`next-step` 填写描述并发布。WebUI 展示任务结果，可继续既有准备任务或保存草稿。
成功回读后计入正式发帖数，未知结果先核对原动作。

### Agent 主加流程

```text
用户向 Agent 指定账号和一个明确博主
→ Agent 只读目标主页和当前关注状态
→ 默认无需审批；用户特别说明时才暂停确认
→ Agent 关注一次并回读“已关注”或“互相关注”
→ WebUI 只展示任务状态和结果
```

对应的原子命令是：

```powershell
python scripts/cli.py --account <账号别名> follow-user `
  --user-id USER_ID --xsec-token XSEC_TOKEN
```

关注属于单向操作，默认直接执行且无需审批；只有用户特别说明时才等待确认。每个目标仍只点击一次
并单独保存回读结果。测试账号已完成两个随机目标的真实关注验收。

### Agent 私信流程

```text
用户指定账号及 1–10 个明确收件人
→ 用户说明每位收件人的联系目的
→ Codex 只读判断首次私信或已有会话，并读取近期上下文
→ Codex 为每个收件人生成不同的最终文本
→ 当前任务直接发送
→ 逐人发送、回读和记录；一人失败不阻断其余人
→ 恢复批次只重试 FAILED 或 BLOCKED 项
→ WebUI 只读展示批次与逐人结果
```

点击发送后无法回读是否成功时记为 `RESULT_UNKNOWN`，不会自动重发。首次私信只有在目标主页向当前
账号展示私信入口时才能执行；系统不会改用评论等其他联系方式。执行链已通过自动化测试，真实发送
仍需用户明确指定验收账号、目标和联系目的。

### WebUI 新私信回复

1. 在“外发草稿确认”找到“新私信智能回复”；
2. 选择 READY 账号和最近会话数量，点击“读取私信收件箱”；
3. 系统只保留最后一条由对方发送的文字，跳过自己的最后发言、表情、语音和平台提示；
4. 点击“生成 AI 私信草稿”，结合近期会话得到待确认文本；
5. 在草稿区核对账号、发件人、原文和最终回复，确认后才发送；
6. 发送后必须回读到新的己方消息气泡；无法回读时记为 `RESULT_UNKNOWN`，不得直接重发。

私信收件箱采集和草稿生成都是只读或本地操作。只有第 5 步的最终确认会触发真实私信发送。

## 10. 评论和回复

### 随机评论

1. 在“立即任务”中选择已经 READY 的目标账号；
2. 任务模板选择“随机评论”；
3. 选择评论风格，并设置发送数量、候选池和最长搜集时间；
4. 点击“创建并直接发送”。

系统会从首页推荐中搜集候选，随机抽取 1–3 篇，读取笔记标题和正文，生成相关评论后直接发送。
这次点击只授权当前账号和本次显示的数量；不会进入逐条确认，也不会建立后台持续评论计划。任务结束后
可展开结果查看每篇目标笔记、实际评论文本和成功或失败状态。

### 指定笔记评论和回复（V1.0 当前流程）

评论和回复在“外发草稿确认”中采用“先保存、再确认、后执行”：

1. 选择目标账号；
2. 选择“评论笔记”或“回复评论”；
3. 评论填写笔记 ID，回复填写评论 ID；
4. 填写目标说明，帮助确认时识别对象；
5. 编辑最终文本并保存草稿；
6. 点击“核对并确认”；
7. 核对账号、UID、目标和完整文本；
8. 输入目标笔记 ID 与当前 XSEC Token 后执行。

草稿一旦修改，旧确认自动失效；一次确认只能执行一次。
重新确认同一草稿时，上一份尚未使用的确认也会失效。成功执行后草稿显示“已执行”；结果无法
确认时显示“结果待核对”。

若结果显示 `RESULT_UNKNOWN`，表示平台可能已经收到操作，但系统没有得到可靠结果。必须先打开
小红书页面人工检查，不能直接重发。

### Codex 评论与私信回复

用户先在 WebUI 为账号配置并启用回复规则。随后在 Codex 中调用 `$xhs-reply`，或依次执行：

```powershell
python scripts/cli.py --account <账号别名> reply-inbox collect --limit 20
python scripts/cli.py --account <账号别名> reply-inbox list --state NEW --limit 20
python scripts/cli.py --account <账号别名> reply-inbox context --event-id <事件ID>
```

Codex 为每个事件读取笔记或会话、账号人设、知识和近期回复，生成 `reply` 或
`skip` 决策。决策写入 UTF-8 JSON 文件后执行：

```powershell
python scripts/cli.py --account <账号别名> reply-inbox apply `
  --decision-file "C:\绝对路径\reply-decision.json"
```

Agent 生成的 `reply` 直接进入现有 Python/Bridge 发送链；无需回应的内容进入 `skip`。私信发送前重新核对对方最新连续消息；发送后必须取得页面回读。

WebUI 的模型设置、生成草稿和 `reply-cycle` 属于 API 模型兼容流程；Codex 回复收件箱不依赖该模型
配置。详细结构和验收边界见 [V2.0 Codex 回复说明](AUTO-XHS-V2-INTELLIGENT-REPLY.md)。

## 11. 使用 Codex 操作

在 Codex 中打开本项目工作区后，用自然语言明确说出账号槽位和目标。例如：

```text
使用 brand-a 搜索“露营装备”，只读取结果，不点赞。
```

```text
使用 brand-b 搜索“手冲咖啡”，找出互动最高的三篇并总结。
```

```text
为 brand-a 的这篇笔记准备一条评论草稿，但不要发送。
```

涉及私信、主加、点赞、收藏、评论或回复时，应明确目标账号。主加属于单向操作，Agent 默认直接预览、执行
并回读，无需审批；V1.0 评论和回复仍需在 WebUI 核对最终草稿。发布也不会因为使用
Codex 而自动开放。V1.5 目标规则必须等对应代码和验收完成后才能启用。

## 12. 多账号使用原则

- 每个槽位对应一个固定 Chrome Profile；
- 不同账号任务可以并行；
- 同一个账号的任务自动串行；
- V1.0 由用户手动保持目标 Chrome Profile 和小红书页面在线；
- 切换小红书登录身份前，先暂停该账号业务；
- 电脑迁移、扩展重装或撤销配对后，需要重新配对；
- 普通重启不需要重新配对。

## 13. 暂停和配额

- 顶部“暂停全部任务”会阻止新任务开始，不会强行中断已经到达平台的动作；
- 全局并发可以设置为 1–3；
- L1 设置包含每小时限额、每日限额、重复目标间隔和失败熔断阈值；
修改配额属于运行配置变更，WebUI 会要求再次确认。

## 14. 查看结果

任务可能出现以下状态：

| 状态 | 含义 | 应对方式 |
|---|---|---|
| `SUCCESS` | 已获得明确成功结果 | 查看执行记录 |
| `BLOCKED` | 条件不满足，任务没有正常开始 | 按推荐动作恢复账号 |
| `FAILED` | 已获得明确失败结果 | 修复参数或连接后重新创建任务 |
| `RESULT_UNKNOWN` | 可能已执行，但结果无法确认 | 先到平台人工检查，不能直接重发 |

账号未就绪导致的 `BLOCKED` 也会进入执行记录，便于追踪为什么没有开始。恢复后可以在任务卡片
点击“重试”；不再需要的排队中、待确认或阻塞任务可以取消。

## 15. 日常启动和关闭

日常使用：

1. 双击 `start-auto-xhs.cmd`；
2. 在 WebUI 账号页点击目标槽位的“启动账号”；
3. 系统启动或复用 Bridge；扩展未连接时按需打开已绑定 Profile；
4. 保持目标小红书页面登录，并核对 Profile、扩展实例和 UID；
5. 账号显示 READY 后再执行任务。

关闭 WebUI 页面不等于停止后台 Bridge。正常使用时可以让 Bridge 保持运行；不要在任务执行期间
直接结束未知 Python 或 Chrome 进程。

联合启动代码和自动化测试已经完成；真实 Windows 环境若未能打开正确 Profile，按账号卡片的
“下一步”恢复并导出诊断，不要手动把其他已打开窗口当作目标槽位。

## 16. 诊断与故障恢复

遇到问题时先查看账号卡片的“下一步”。还不能解决时，在设置区点击“导出脱敏诊断”，报告会
保存到本机产品数据目录。

详细恢复步骤见 [故障恢复指南](TROUBLESHOOTING.md)。

## 17. 本地数据位置

默认数据位置：

```text
账号槽位：%USERPROFILE%\.xhs\accounts
通用扩展代码：<项目根目录>\extension
任务与诊断：%USERPROFILE%\.xhs\auto-xhs
```

删除项目目录不会自动删除这些数据。卸载或迁移前，先确认是否需要保留任务记录和账号槽位。

不要把以上目录、Chrome Profile、配对信息或诊断中的私密内容提交到 GitHub。

## 18. 最短上手清单

```text
取得项目
→ 双击 start-auto-xhs.cmd
→ WebUI 添加已有 Chrome Profile
→ 在目标 Profile 加载通用扩展
→ 启动账号
→ 发起并完成配对
→ 检查并确认 UID
→ 账号显示 READY
→ 先执行一次搜索测试
→ 再使用点赞、收藏或草稿确认功能
```

完成这条链路后，再逐个添加其他账号。

## 按行为查看执行记录

左侧账号及栏目导航切换时保留点击前的页面滚动位置，方便在当前阅读区域继续查看。

“今日目标 / 实际”集中展示各项指标的目标、实际数量与状态。
具体操作对象、内容及逐项结果统一在下方“执行记录”中查看。

进入账号详情的“执行记录”，可以查看浏览、点赞、收藏、评论、关注博主、评论回复、
私信回复、私信发送、发布和巡检采集。各组显示行为记录的结果汇总，展开后按轮次查看
操作对象、执行时间、本次文本、收到的内容与结果说明；最新一轮默认展开。

复合任务中的行为独立呈现结果。浏览采用逐篇完成记录；评论、关注、点赞等写入操作
采用平台回读确认。结果待核对、已跳过、未执行、等待执行和执行中均分别展示，
目标状态已满足时显示“已满足”。历史回执缺少逐项结果时显示“待核对”。

巡检采集按轮次展示粉丝、获赞、评论和私信渠道的完成情况、采集数量及截至时间。
“本次采集记录”可能包含历史数据；本轮新发现数量按回执单独显示，每日新增查看
“今日目标 / 实际”。渠道结果缺失显示“未采集到结果”，明确采集完整后才显示空结果 0。
回复结果独立列在评论回复或私信回复组；本轮没有待回复消息时显示“无需执行”。

分组中的数字统计行为记录。同一待处理事件可能出现在多轮巡检记录中，轮次明细保留
各轮结果。任务编号、命令、轮次编号和执行归属位于“技术信息与执行归属”。
