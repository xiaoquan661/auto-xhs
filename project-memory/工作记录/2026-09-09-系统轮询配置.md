# 系统轮询配置

## 结论

根据用户要求，机器与账号状态检查默认每 10 分钟一次。系统设置增加“定时轮询”表单，
提供周期、用途、最近完成和预计下次时间；保存后生效并持久化至经理状态文件的 `settings.polling`。

| 配置 | 默认间隔 |
| --- | --- |
| 机器与账号检查 | 600 秒 |
| 执行结果回收 | 300 秒 |
| 经理 Agent 任务轮询 | 5 秒 |
| 记忆经验审核 | 60 秒 |
| 运营台页面刷新 | 30 秒 |
| 任务详情刷新 | 5 秒 |

后台启动时执行首轮；后续按上一轮完成时间和配置间隔安排。修改参数不会中断在途操作。
记忆审核由经理 Agent 周期承载；页面隐藏时暂停页面刷新。
机器与账号状态有效期为检查间隔的三倍，默认 30 分钟；收到明确异常仍即时更新状态。
账号周期检查读取连接状态和已有身份核验记录，实时平台身份核验仍由“检查身份”入口执行。

## 实现与验证

- `scripts/manager_polling.py` 统一字段、范围和默认值，配置更新由现有 WebUI 会话保护。
- `GET/POST /api/v1/manager/polling-settings` 读取和保存配置，控制台快照包含 `polling`。
- `manager_sync_service.py` 与 `manager_agent_service.py` 在运行中使用新间隔；
  `manager_service.py` 采用同步调整的状态有效期。
- `webui/manager-polling.js` 保留未保存输入和失败后的编辑值，页面自动刷新使用保存后的配置。
