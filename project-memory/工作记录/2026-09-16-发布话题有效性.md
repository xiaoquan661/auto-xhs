# 发布话题有效性

日期：2026-09-16。范围：经理机、PC057、PC052 的图文与视频共用发布表单。

## 现象与依据

用户反馈所有井号标签均可能显示为黑色普通文字，并确认当前没有保留编辑页。
源码 `_input_single_tag` 点击第一个候选后直接记成功，未确认生成话题节点；找不到候选时
输入空格继续。泛用点击还会选择候选的可点击祖先并聚焦，不能保证候选与编辑器选区保持一致。
这些是已确认的实现缺口；原现场中导致所有标签失效的具体步骤尚未实机复现。

从 PC057 当前 RedNote 创作中心取得的前端资源中确认：候选 `.item .name` 显示话题名，
候选自身的 Vue onClick 调用平台选择逻辑；有效节点为 `a[data-topic]`，内容包含 `id`、`name`。
平台生成中的 `newTopic_Id` 尚不算已确认的话题 ID。
原始资源与部署证据位于 `output/publish-topics-20260916/`。

## 实现

- 精确匹配可见同名候选，直接触发候选自身的选择事件并保留正文选区。
- 逐个等待平台生成带 ID 的话题节点；每次输入后核对已经输入的全部话题。
- 每个话题输入前将光标移到段落末尾；完成后失焦回读，表单完成前再次核对全部话题。
- 未找到同名候选或话题未生效时返回 `PUBLISH_TOPICS_NOT_CONFIRMED`，保留具体话题名。
- 新增 `tests/test_publish_topics.py`，覆盖候选匹配、延迟确认、普通文字识别、连续输入与失焦。

源码：`scripts/xhs/publish.py`。本次为 Python 修复，扩展无需重载。
