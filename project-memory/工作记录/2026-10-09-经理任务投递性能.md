# 经理任务投递性能

日期：2026-10-09。范围：经理机任务投递与状态存储。

经理状态文件约 75 MB。下发一批时，任务创建、SFTP 传输状态、员工接收回执原先会多次完整读取和写入该文件；经理 WebUI 与回收流程同时写入时，10 秒锁等待可能超时。员工已接收、经理写回超时的批次需按原任务编号对账。

经理状态存储现采用更快的 JSON 编解码，并在文件没有变化时复用进程内读取结果；外部进程完成写入后，下一次读取会刷新。SFTP 唤醒成功后，员工消息、执行状态和最终接收状态在一次经理状态事务中提交。任务首次创建与传输状态仍分别落盘，保留中断后的同编号对账依据。

以当前约 75 MB 的经理状态文件在临时副本上测量：连续读取五次由 9.83 秒降至 0.56 秒；单次写入由 3.57 秒降至 0.96 秒；三项合并写入由 3.48 秒降至 1.20 秒。测试副本未写入业务状态。经理端 324 项 Python 测试通过，Ruff 检查及差异检查通过；依赖锁定离线校验通过。本机经理服务已重载，真实运营台快照接口返回 HTTP 200、5 台机器和 11 个账号，既有任务只读查询在 1.54 秒内返回。

来源：`scripts/manager_store.py`、`scripts/manager_service.py`、`tests/test_manager_store_batch.py`、`tests/test_manager_service.py`、`pyproject.toml` 与 `uv.lock`。本次没有新下发业务任务；下一次实际批量投递的耗时需在该轮接收确认后记录。
