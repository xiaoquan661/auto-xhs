# 私信与通知采集运行核查

日期：2026-10-14。工程归集：2026-10-16。

## 入口与前置条件

- 评论/@与新增关注沿固定通知采集入口执行；每日通知复用对应采集能力。
- 私信采用独立 `collect-private-messages` 入口，分页覆盖与空态确认分别记录。
- `run_reply_cycle` 包含采集与回复，执行前要求回复规则与槽位平台匹配。
- 独立只读采集、包含回复的周期流程和 Windows 定时任务分别验收。

平台、调度开关、规则与计划任务状态各有职责，作品定时采集不能替代消息巡检的启用证明。
页面/API 超时与员工采集故障分开诊断，可先用经理数据库定向查询核对既有回执。

## 验证与来源

历史专项私信测试 29 项、通知测试 35 项、应用服务相关测试 3 项通过；
这些测试组存在重叠，按各自执行结果登记。

源码依据为能力注册表、应用服务、业务 runner、私信收件箱与历史采集器、
通知即时及每日采集入口、经理回收与数据库导入。模块由
[源码布局](../../source-layout.json) 定位，CLI 入口见[项目首页](../../README.md)。

持续巡检需要另行核对计划任务启用、参与账号、平台规则及实际回执。
原始机器配置和业务查询结果由本地受控存储保存。
