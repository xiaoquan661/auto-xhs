# PC071 私信与通知链路验收

日期：2026-10-14。工程归集：2026-10-16。

## 技术结论

私信采集、回复执行、平台会话回读和经理入库分别形成证据。发送确认采用
`outgoing_message_present` 与 `platform_conversation_readback`，任务接收与业务完成分别判定。

历史通知采集曾出现页面存在通知卡片、解析结果却为空的情况。排查应沿标签定位、
选中状态、卡片结构和历史覆盖继续核对；标签角标只代表页面状态。
通知定位与历史分页后续修复见[经理状态锁与收到通知采集修复](2026-10-14-经理状态锁与收到通知采集修复.md)。

## 工程验收方法

1. 核对固定账号槽位、Chrome Profile 和 Bridge 的连接关系。
2. 检查员工执行输出与平台回读，再核对 outbox 中的业务结果。
3. 经理回收结果后，分别检查任务投影和员工回复业务表。
4. 测试规则的结束状态按授权安排恢复，周期启停独立验收。

入口为项目固定 CLI；页面实现位于员工源包的 `runtime/scripts/xhs/private_inbox.py`、
`notifications.py`、`growth_notifications.py` 和 `notification_history.py`。
经理归档与导入沿 `manager_service.py`、`manager_database.py` 维护。

来源为当日受控执行输出、截图及经理导入核对；原始业务证据由本地存储保存。
本记录说明历史验收方法，不作为设备当前状态。
