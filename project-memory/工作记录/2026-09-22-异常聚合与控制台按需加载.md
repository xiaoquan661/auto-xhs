# 异常聚合与控制台按需加载

2026-09-22，针对异常中心重复提示、账号采集与控制台返回耗时完成调整。

## 原因与实现

- 异常中心原先同时展示失败任务和其回执，并将历史成功回执缺少部分协议字段判为异常。现在优先使用最新回执，同一任务只展示一次；同账号、能力、状态和错误码的记录合并，显示次数及最近一次内容。
- PC052/xiix 由用户确认封禁且已暂停调度。其普通采集失败归入账号暂停提示，结果未知仍独立保留。历史回执保存在数据回收审计中。
- 每日计划排除暂停账号；下发新任务时先检查暂停状态，再加载任务上下文。普通每日运营默认直接执行计划动作，作品指标采集由独立任务触发，也可显式配置 collect_work_metrics=true。
- 运营汇总读取经理机已有数据，页面刷新不触发平台采集。首页呈现今日计划、实际动作和账号记录；历史运营总览表格已移除。
- 普通快照延迟返回回执历史、Agent 消息及调试记录，分别由数据回收、任务详情、系统设置按需读取；页面只渲染当前工作区的主要面板。
- 经理状态 JSON 约38 MB。原查询读取等待后台写锁，实测一次31.58秒。只读视图改为读取经原子替换发布的完整文件，写入仍保留事务锁；每个请求取得独立一致快照。

## 验证与生效

- 本次实页异常提醒由212条合并为73项，xiix 显示暂停说明；历史审计成功加载134条回执。
- 普通快照约10.00 MB降至5.23 MB。经理服务重载后一次实际HTTP请求2.60秒返回；这是当次测量，持续负载下耗时可能变化。
- Python相关回归、前端异常聚合及按需加载测试、员工面板测试、Ruff与语法检查通过。只读视图测试验证读取不进入写事务、既有视图稳定以及新请求读取最新文件。
- 经理服务通过项目 web_lifecycle 重载。变更作用于经理查询、每日调度和本地前端；平台采集及互动未作为本次验证动作执行。
