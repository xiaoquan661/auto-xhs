### 存储与分层

| 层次 | 实现 | 用途 |
| --- | --- | --- |
| 共享核心 | `.mempalace\palace\chroma.sqlite3` 中的 `shared_core` | 身份、表达风格、美学、场景、边界、已批准知识；治理规则与人格文件另外加载 |
| 员工长期记忆 | 同库 `resident_long_term`，按 `resident_id` 筛选 | 保存各员工经过批准的专业经验 |
| 员工短期记忆 | `memory/resident_short_term.py`，每个 Resident 一个 SQLite 文件 | 会话、任务、内容、摘要、来源、过期时间；默认有效期 168 小时，可配置 |
| 运行事实与会话交接 | 动作回执、`short_term_memory.json`、`runtime_facts.jsonl`、动作增量文件 | 保存执行结果、观察、统计与异常，支持运营交接和追溯 |

`short_term_memory.json` 是会话交接产物，与 Resident 的 `short_term.sqlite3` 是两种存储。当前 intake 不会自动把会话交接 JSON 写入该 SQLite 数据库。

### 产生、回传与入库

1. `deployments/pc027_daily_operator_v1/pc027_daily_operator.py` 在会话中累计观察与专业学习，终态输出 `short_term_memory.json`；专业学习从动作结果接收，不能据此认定控制器本身会自主推理知识。
2. `runtime/pc055_fleet_daily_ops_collector.py` 从员工端收取动作回执与会话结果。
3. `C:\mila\simulation\manager\manager_result_import_poller.ps1` 依次执行结果导入、建议提取、日常回收、记忆 intake 和运营数据整理。
4. `runtime/pc055_daily_ops_memory_intake.py` 按动作和会话标识去重，自动追加运行事实，保存动作增量；默认目录是 `data/runtime/daily_operator_memory_intake/`。专业学习交给建议队列，初始状态为 `pending_review`。
5. `runtime/manager_memory_suggestions.py` 提供提取、批准、拒绝和导入操作，批准时检查重复和冲突。`memory/mempalace_store.py` 对共享核心和员工长期记忆要求 `architect_approved=true` 且 `reviewed_by=Mila Architect`。
6. `runtime/manager_auto_memory.py` 另有任务结果、员工状态及低风险运行事实建议的自动入宫殿能力。本次在当前结果回收 poller 中未发现其调用；不能把它等同于所有运行事实都已自动进入宫殿。

这里的 Mila Architect 是批准角色。批准函数可以由程序调用，并写入该角色标记；代码本身不能证明每条记录都经过人工点击或模型语义审核。当前 poller 提取建议，未执行长期记忆自动批准。

### 召回与使用

- `memory/resident_memory_router.py` 返回的顺序为：治理规则 → 共享核心 → 本员工已批准长期记忆 → 当前会话短期记忆 → 当前任务上下文。
- `scripts/mempalace_wake.py` 生成压缩后的启动召回文本，`runtime/mila_boot_loader.py` 将它与人格、角色和启动文件组合。
- 宫殿当前 `sqlite_search` 实现是读取 SQLite 文档、按元数据过滤、以词项匹配打分排序；不能只根据文件名把它描述为成熟的语义向量检索。未命中词项的记录也可能进入返回结果。
- `recent_relevant` 支持短期记忆相关性排序；当前 Router 传入 `session_id`，默认只读当前会话。跨会话经验持续使用需要另外验证。
- `runtime/prepare_employee_daily_ops.py` 的 `resolve_group_intro_backlog` 会读取历史会话交接及动作回执，已有特定业务的历史复用。
- 通用 Router 不读取 `runtime_facts.jsonl`。日常事实回收、特定业务复用和通用人格召回目前是不同路径；本次没有逐台验证员工任务是否完整消费召回内容。
