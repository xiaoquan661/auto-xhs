# 作品数据同步与页面刷新

日期：2026-10-08，北京时间。

## 数据路径

员工 CLI 的作品采集由 `ApplicationService._record_metric_collection` 写入员工本地 `operations.db`。经理端定期导入员工业务表；员工任务回执也可通过 outbox 独立导入经理结果库。运营台快照合并经理回执和员工业务表镜像，浏览器请求快照后更新画面。

## 原因与改动

- PC071、PC065、PC073 的机器记录未配置 `business_data_sync_enabled`，后台此前仅同步显式开启的机器，导致单独 CLI 采集结果留在员工本地。后台现默认同步业务数据库，显式关闭配置仍生效；三台机器的既有数据已补同步。
- 采集结束后的刷新可能复用先前已经发出的请求。前端现等待旧请求结束后重新读取快照，并在读取失败时保留明确的刷新失败提示。
- 经理库导入与页面读取可能争用 SQLite 写锁。经理查询库现启用 WAL，使页面读取已提交快照；业务库同步从原子状态快照取数，避免在数据库重建期间持有经理状态写锁。
- 运营任务轮询逐项反复读取约 71 MB 状态文件。现每轮复用一次读取的快照及进度输入。
- 在线快照计算与后台回收在同一 Python 进程相互拖慢；本机单独计算约 7–12 秒，在线曾超过请求时限。Web 服务现复用一个独立进程计算仪表盘快照，每次请求读取当前提交状态。

## 验证

- 经理数据库、同步服务、业务服务专项 86 项测试通过；增加任务轮询回归后，经理服务及 Agent 服务 85 项测试通过。
- 新仪表盘读取进程与 Web 路由 67 项测试通过，覆盖跨请求读取新增指标。前端验证覆盖采集结束时旧请求未完成、回执成功但刷新失败两种情况；既有作品展示测试通过。
- 三台补同步结果：PC071 导入 488 条、PC065 导入 14 条、PC073 导入 9 条业务记录；经理数据库实查日志模式为 WAL。
- 经理服务已重载。独立读取进程启用后，实际 `/api/v1/manager/dashboard-snapshot` 返回 HTTP 200，首次约 13.41 秒；PC071 三个槽位的最新作品快照分别为 13:10:40、13:11:43、13:11:51。
- 证据：`tmp/creator-refresh-fixed-dashboard.json`；诊断耗时与线程记录位于 `tmp/dashboard-refresh-profile.prof`、`tmp/live-dashboard-*.prof`、`tmp/dashboard-thread-trace.log`。正式服务运行入口为 `scripts/web_server.py`。

## 使用与范围

刷新浏览器页面一次以加载本轮前端代码。之后即时采集结束会重新读取展示数据；员工独立 CLI 的结果通过后台业务库同步进入经理端。页面指标时间仍代表实际采集时间，导入时间代表经理接收时间。

PC071 的作品采集范围及每日任务覆盖情况仍参见[作品采集功能核对](2026-10-08-作品采集功能核对.md)；本次变更处理数据同步与页面刷新。
