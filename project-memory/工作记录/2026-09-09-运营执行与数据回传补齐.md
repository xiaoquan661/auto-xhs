## 实现结论

| 编号 | 功能 | 实现与边界 |
| --- | --- | --- |
| BACKEND-01 | 每日计划执行 | 新增已保存计划准备接口与 CLI，按账号和计划版本生成运营任务；内置规划支持发布准备、评论回复、关注和增长数据采集。发布素材、回复内容与目标由动作输入提供。发布准备进入真实预览确认，确认后的最终结果可继续回收。 |
| BACKEND-02 | 运营策略执行 | 经理下发与员工应用执行读取账号配置，检查当日发布上限、间隔、结果待核实和运营时间窗口；结构化异常规则按回传状态码检查。CLI 最终发布同样检查发布策略；草稿独立于正式发帖数量限制。平台验证状态的识别覆盖仍取决于已有状态采集。 |
| BACKEND-03 | 运营规划依据 | 主页滚动采集历史笔记，记录覆盖范围，补读缺少时间的笔记详情；聚合历史发布时间、跨日入站互动和成功评论回执，排除已确认关注的目标。默认存在采集数量限制，样本保持样本口径。 |
| BACKEND-04 | 增长及关系数据 | 新增关注与获赞通知采集、事件去重与回传；保留可见日期和首次观察时间的区别，无平台日期的历史事件不计作当日新增。连续快照差值保持采样净增口径，小红书关系动作为关注。 |
| BACKEND-05 | 评论位置和平台链接 | 采集器保留平台给出的评论或笔记链接，适配 RedNote 域名；只有笔记链接时返回评论编号、评论者和内容线索，页面明确显示打开笔记。 |
| BACKEND-06 | 私聊位置与状态 | 返回实际会话地址和采集前未读标记，平台阅读状态与系统处理状态分别展示；未读标记缺失时返回 UNKNOWN。 |
