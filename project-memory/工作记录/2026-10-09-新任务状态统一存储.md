# 新任务状态统一存储

日期：2026-10-09，北京时间。

## 结论

经理机新建任务及其员工回执以 `manager-operations.db` 的 `records` 为权威记录。新任务创建后，任务状态更新和对应回执写入同一 SQLite 库；经理服务的任务列表、结果列表和运营台快照从同一库读取这些记录。新任务在 `live_task_ids` 中登记，回执在 `live_result_keys` 中登记。原有任务继续由经理状态文件读取。

经理数据库整体投影保留实时任务与回执行，避免历史查询刷新覆盖新状态。其他经理配置和运营状态仍保存在 `manager-state.json`。员工业务执行及 outbox 回收链路保持原有时序。

## 来源

- `scripts/manager_live_records.py`：新任务与回执的 SQLite 事务写入和读取。
- `scripts/manager_store.py`：新任务切换、经理读取视图和批量回执提交。
- `scripts/manager_database.py`：整体投影与实时记录共存。
- `tests/test_manager_live_records.py`：新任务、回执、经理视图及整体投影验证。

## 验证与下一步

本地专项回归通过。当前改动位于开发分支，经理在线服务仍使用原运行目录；合入并重载后，以新下发任务的任务 ID 核对下发返回、数据库 `records` 与运营台接口，并分别确认员工接收和业务完成状态。
