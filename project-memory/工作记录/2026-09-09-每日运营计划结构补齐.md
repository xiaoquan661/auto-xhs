## 当前实现

- `scripts/daily_operations_plan.py`：按日期、账号阶段、压力和采集证据生成建议；构造版本化执行材料，区分硬指标、机会预算和观察指标。
- `scripts/daily_operations_runner.py`：按时间窗口、间隔、剩余预算和回执逐项派发；保留结果未知预算与候选排除信息。发布、回复和关注输入复用经理规划器，缺少目标或素材时保留待办。
- `scripts/manager_service.py`、`scripts/manager_store.py`：增加生成、预览、显式提交与关联记录的原子保存；每日计划保留历史版本和提交引用。
- `scripts/employee_operations.py`：日报逐项封顶核销，关注单独统计；携带每日材料的跨日回执归属原计划日期。目标页、任务页与日报使用提交时的当日动作基数和已提交版本。
- `webui/employee-panel.js`、`scripts/manager_cli.py`、`scripts/web_server.py`：建议、预览、提交入口及浏览、回复字段。
- 现有首页浏览、随机评论适配器增加按用户 ID 排除候选的参数。
- `operations_policy.py`、应用服务和发布工作流：员工执行前检查每日窗口与实时 UID，最终发布确认受每日窗口限制，保存草稿沿用既有流程。
- 使用说明：[员工机运营数据与共享计划](../../docs/EMPLOYEE-OPERATIONS.md)。

## 统一后的调用关系

`generate` 生成草稿，`save` 留存版本，`preview` 返回执行材料，`submit` 原子创建目标与运营任务。
兼容 `prepare_daily_plan` 入口调用同一个提交实现，相同版本重复提交返回同一组任务。
`daily-plan inputs` 和 `/operation-tasks/{id}/daily-inputs` 追加动作数组；已登记项保持不变。
每日执行器复用已有 `action_inputs` 规划与 Worker 回收链路，发布准备进入真实预览确认。
