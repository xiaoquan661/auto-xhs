# 管理台响应恢复

时间：2026-10-14 上午，北京时间。范围为经理机 WebUI `8765`。

管理台当时仍有 `0.0.0.0:8765` 监听，`web_server.py` 主进程从 10 月 13 日 14:41 持续存在，但本机首页和健康接口在 12 秒内无响应，局域网入口也无法正常打开。错误日志中多次出现 `dashboard-snapshot` 等待 60 秒后 `TimeoutError`；现场物理可用内存一度约 259 MB。现有 `AutoXHS-Manager-WebUI` 计划任务只检查端口监听，并以 `Start-Process -Wait` 等待服务进程，因此服务占端口而失去响应时不会自动恢复。

清理失去响应的 WebUI 主进程与其遗留的仪表盘子进程，结束原计划任务实例；随后使用项目 `web_lifecycle.py start` 从后台启动服务。恢复后，本机与局域网的首页及 `/api/v1/health` 均返回 HTTP 200；`dashboard-snapshot` 一次回读 HTTP 200，约 13.4 秒、18.9 MB。员工机及账号业务任务未在本轮操作。

来源与验证：`Get-NetTCPConnection`、`Get-CimInstance Win32_Process`、`Get-ScheduledTask`、`tmp/webui-scheduled-error.log`、本机及 `192.168.110.165:8765` HTTP 回读。后续需将计划任务从端口存活检查改为健康接口检查，并让计划任务每轮独立退出；当前端口存活但服务失去响应时仍有再次发生的可能。
