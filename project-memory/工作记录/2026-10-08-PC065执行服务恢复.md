# PC065 执行服务恢复

## 结论

运营台 PC065/4-1 的账号状态提示源于员工机本地执行服务停止。经理机到 PC065 的 SSH 认证正常，但员工机 `127.0.0.1:8766` 未监听，固定入口 `executor-status` 返回 `STOPPED`。使用 `start-executor` 启动服务后，健康回读为 `healthy=true`、`executor_service.ready=true`、机器 `PAUSED`。

PC065 已登记 `AutoXHS-PC065-Executor-Service` 登录启动任务，使用员工机项目虚拟环境的 `pythonw.exe` 启动 `scripts/executor_server.py --port 8766`。计划任务注册及动作已回读；下次登录自动启动效果尚待实际登录验证。

同日后续 Bridge 重启提示“没有找到由本项目登记的 Bridge 进程”。员工机 9333 端口无监听，`bridge-process.json` 不存在。该重启入口先停止已登记进程；此时使用 `account-action` 的 `bridge-start`，只启动本地 Bridge，不打开 Chrome Profile。启动后进程登记为 PID 7680，远端 `account-status` 回读 Bridge、扩展连接和 Profile 配对均为 `READY`。

用户确认机器持续运行、由账号槽位开关控制调度后，经理机执行 `machine resume --machine-id PC065`。当前经理状态为机器 `READY`、`desired_paused=false`、`remote_paused=false`；4-1 的 `scheduling_enabled=true`、`health_state=READY`、`connection_ready=true`。账号详情圆点改按账号槽位健康状态着色，已通过 PR #39 合入 `main`，经理 WebUI 实际服务目录中的脚本也已更新并经 HTTP 200 回读。
