# 架构手册采集留存与执行分工

## 手册内容

系统总览把账号与素材来源的接入绑定、按本次发布需要准备素材、SFTP 传输素材、
任务 JSON 投递分别表述。计划复用绑定，发布任务引用员工机已经就绪的素材绝对路径。

新增“运营数据采集与留存”章节，分别展示手动采集入库、员工每日采集及经理后台回收。
手动作品与通知入口经经理 API、SSH 调用员工固定采集程序，同步接收 result，再导入员工业务表。
后台结果线程通过 SFTP 增量回收 outbox，同轮按机器开关通过 SSH 只读导出业务表。

经理 Windows 任务负责登录及周期检查后按需启动 Web 服务，Web 服务内的
ManagerSyncService 线程执行回收。2026-10-16 本机配置回读 results_seconds=180，
源码默认值 300；机器账号检查 600 秒，页面刷新 30 秒。员工 Creator-0030 的默认时点为
北京时间 00:30，各机任务启停和参与账号以目标机配置为准。

当前留存位置为 `C:\auto-xhs\manager-state\manager-operations.db`。图与 FAQ 说明
`records`、`worker_records`、`metadata`、查询投影 `daily_metric_facts`，并区分即时回执保存、
业务表导入和完整数据库投影刷新。原始回执缓存位于 `collector/{machine}/records`，
按经理回收日期归档到 `daily_receipts/{date}/raw/{machine}/{task}/{sequence}.json`。

手动入口与回收标出 MANAGER-FRONT-05 / 1.0、MANAGER-04 / 1.5，员工指标采集对应
DATA-03 / 1.5；FAQ 列出任务编号、正式包相对目录、绝对入口和职责源码位置。
所有图中节点分别标明操作人、经理 Agent、员工 Agent、经理程序、员工程序或 Bridge／扩展程序；
混合节点显示相应参与者，关键节点 FAQ 补充分工。
